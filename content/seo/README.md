# ZEROデザイン SEO記事 企画・管理の仕組み

思いつきで記事を書くのではなく、**発見 → 優先順位づけ → 執筆 → 公開 → 効果確認 → 次の記事**
を継続的に回すための運用ルールです。

## ファイル構成

```
content/seo/
├── README.md              ← このファイル（運用ルール）
├── article-ideas.json     ← 記事ネタ管理ファイル（本体）
└── search-console/        ← Search ConsoleのCSVを置く場所（任意）
```

※ `content/` はNext.jsのビルド対象外です。サイトの表示・速度には影響しません。

---

## 1. 作業開始時に必ず確認する4点

「次に書く記事を考えて」「今週の記事を3本選んで」などの指示を受けたら、
**必ず最初に以下を確認**してから提案すること。

| # | 確認対象 | ファイル |
|---|---|---|
| 1 | 記事ネタ管理ファイル | `content/seo/article-ideas.json` |
| 2 | 公開済み記事 | `src/data/posts.ts` |
| 3 | サイトカテゴリー | `src/data/blogCategories.ts` |
| 4 | サービスページ | `src/data/services.ts` / `src/app/services` / `src/app/sns-ai-video` |

確認せずに記事を提案しないこと。**既存記事との重複が最大のリスク**です。

## 2. ステータス

| status | 意味 | 次のアクション |
|---|---|---|
| `idea` | 記事候補（未着手） | 優先度を見て `planned` へ |
| `planned` | 執筆予定（公開予定日を設定済み） | 執筆開始で `writing` へ |
| `writing` | 作成中 | 本文完成で `ready` へ |
| `ready` | 公開準備完了（未公開） | 公開して `published` へ |
| `published` | 公開済み | `publishedAt` と `url` を記録 |
| `update` | 既存記事のリライト候補 | 新規記事は作らない |

**記事を公開したら、必ず `status` を `published` に更新し、`publishedAt`（公開日）と `url` を記録すること。**

---

## 3. 優先順位の決め方

```
priorityScore = inquiryPotential*3 + seoPotential*2 + (6 - competition)
```

- `inquiryPotential`（問い合わせにつながりやすさ 1〜5）… **最重視**
- `seoPotential`（SEO上の期待度 1〜5）
- `competition`（競合の強さ 1〜5。強いほど減点）

同点の場合は、次の順で上位にする。

1. ZEROデザインの専門性・独自性が高い（実績・体験を書ける）
2. 既存記事との重複が少ない
3. 内部リンクでサイト全体を強化できる（ハブになる）

> **原則：アクセス数だけを狙った記事を量産しない。**
> ZEROデザインのサービス（クラファン伴走支援 / SNS・AI動画 / ページ制作）と
> 関連の薄いテーマは、数字が良くても採用しない。

## 4. カニバリゼーション（自社競合）対策

新規記事案を作る前に、**必ず既存記事と検索意図を突き合わせる**こと。

- 同じ検索意図の記事が既にある → **新規記事を作らず `status: "update"` として登録**
- 近いが意図が違う → 新規可。ただし `notes` に**差別化ポイントを明記**し、公開後に相互リンクする
- 判断に迷う → 新規を作らず、既存記事の強化を優先する

似たキーワードの記事を増やして自社ページ同士で競合させないこと。

## 5. 記事執筆の基本ルール（AI検索・AI Overview対策）

記事を書くときは以下を必ず守る。

1. **冒頭に結論を書く**（「結論：〜」を最初のH2直下に置く）
2. **H2・H3だけ読んでも内容が分かる**見出しにする（「〜とは」の羅列にしない）
3. **FAQを入れる**（読者が実際に抱く疑問を3〜5個）
4. 一般論で終わらせず、**具体例・数字・手順**を入れる
5. **ZEROデザイン独自の経験・考察**を必ず1か所以上入れる（他社が書けない部分）
6. 目次（`{ type: "toc" }`）を導入文の直後に置く
7. 記事末尾と本文中盤に**CTA**（無料相談）を置く

### 事実確認のルール（重要）

- **手数料・税制・制度・統計は、必ず公式情報を確認してから書く。**
  確認できないものは書かない。推測で数字を作らない。
- 実績数値は**自社で確認できるもののみ**（例：小谷寺 目標500万円→約736万円）
- 事例を紹介するときは、**実在する公開情報**に限る。架空の事例を作らない
- 諸説ある歴史的事項は「諸説あり」と明記する

## 6. 公開時の手順

1. `src/data/posts.ts` に記事を追加（`categories` は必須・1つ以上）
2. アイキャッチを `public/images/posts/` に配置
   - 本文画像 → WebP（200KB以下）
   - アイキャッチ → JPEG（OGP互換のため。200KB以下）
3. `npm run build` でビルド確認
4. `article-ideas.json` の該当項目を更新
   - `status` → `published`
   - `publishedAt` → 公開日（YYYY-MM-DD）
   - `url` → 公開URL
5. commit → push

## 7. Search Consoleデータの活用

CSVを `content/seo/search-console/` に置いた場合、以下の観点で分析し、
結果を `article-ideas.json` に反映する。

| 観点 | 見つけたら | 追加先 |
|---|---|---|
| 表示回数が増えている検索語 | 需要が伸びている | 新規記事候補（`idea`） |
| 平均掲載順位 **11〜30位** | あと少しで1ページ目 | **リライト候補（`update`）※最優先** |
| 表示は多いがCTRが低い | タイトル・説明文の問題 | `update`（タイトル改善） |
| 専用記事がまだ無い検索語 | 取りこぼし | 新規記事候補（`idea`） |
| 順位が上昇中の語 | 伸びしろあり | 記事強化（`update`） |

**11〜30位のキーワードのリライトが、最も費用対効果が高い**ため優先する。

分析後は `searchConsole.lastImportedAt` と `searchConsole.findings` を更新すること。
